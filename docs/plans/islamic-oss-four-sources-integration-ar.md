## مبدأ الحكم (كيف نقرر «يناسب / لا»)

| الحكم | المعنى لعربية |
|---|---|
| **يناسب الآن** | قدرة أو بيانات أو خوارزمية تضيف قيمة فوق سطح موجود، برخصة واضحة، وبدون استبدال Git-first أو Contabo |
| **هجين** | عربية لديها الجزء؛ نأخذ فكرة UX / طريقة حساب / محتوى ناقص فقط، بهويتنا |
| **مؤجّل** | جوال أصلي، بوت كمنتج، سطح مكتب كتطبيق عربية، إشعارات نظام ثقيلة — حتى موافقة صريحة |
| **لا ندمجه** | كود مقفول، أو تبعية API بعيدة بدل بياناتنا، أو خارج هوية المنتج (تحليل كلمة بكلمة)، أو مشروع ميت بلا فائدة فريدة |

**هوية المنتج:** عربية ليست «تطبيق حياة مسلم عام». هي منصة تحليل عربي كلمة بكلمة (قرآن · حديث · تراث) + بوابة أدوات (أذكار، قبلة، مواقيت، إذاعة، موارد). أي دمج يجب أن يقوّي هذا لا أن يحوّلها إلى نسخة من التطبيقات الشاملة.

## 1) tajmeeaton — الحكم التفصيلي

### ما هو؟
تجميعة عربية ضخمة: إسلام + تعريب علوم + لغات برمجة عربية + NLP عربي + خطوط + UX.  
**لا يوجد كود منتج للدمج** — يوجد فهرس وروابط.

### المناسب لعربية (استخراج انتقائي من الفهرس)

| فئة | أمثلة من التجميعة | سطح عربية المستهدف | الحكم |
|---|---|---|---|
| قرآن بحث/بيانات | Alfanous، quran-tajweed، PyQuran، quran org | `/api/search`، مصحف، `/qiraat` | هجين / يناسب (تجويد ملون عند الترخيص) |
| صلاة/مواقيت | batoulapps/Adhan، adhan.py، praytimes.org | `/api/prayer-times`، بطاقة المواقيت | هجين → حساب محلي أوفلاين |
| أذكار | Azkar-App | `/adhkar` | هجين (تذكير/UX) |
| حديث | HadithHouseApi | `/hadith` (Git-first أقوى) | هجين بيانات فقط إن نقص شيء |
| NLP تشكيل/جذر/تصريف | mishkal، Shakkala، qutrub، pyarabic، arabicstemmer | `arabya-nlp` / لغوي | **يناسب** تعزيز المحرك المحلي |
| تصحيح | LanguageTool-ar، ghalatawi | لغوي | هجين |
| صوت/TTS | klaam، festival-tts-arabic | Contabo STT/TTS موجود جزئيًا | هجين اختياري |
| خطوط عربية | Amiri، Aref Ruqaa، Kawkab Mono | هوية المصحف/الواجهة | هجين خطوط مرخّصة فقط |
| شعر/بحور | مولد شعر، كاشف بحر | `/heritage` | هجين لاحق |

### غير المناسب من tajmeeaton كـ«دمج منتج»

- لغات البرمجة العربية، تعريب الرياضيات، مشاريع المقاطعة السياسية، بوتات إسلامية عامة.
- أي مشروع Desktop/CLI كسطح زائر على arabya.org.
- نسخ تطبيقات كاملة بدل تعزيز الطبقات الموجودة.

### الخلاصة لـ tajmeeaton
**مناسب كخريطة اكتشاف دائمة** — لا يُدمَج المستودع نفسه. نحدّث مصفوفة عربية منه عند ظهور أدوات NLP/تجويد مفيدة، وننفّذ فوق Contabo + Git.

## 2) Islamic-APIs — الحكم التفصيلي

### ما هو؟
ملف README يجمع روابط خدمات جاهزة:

| الخدمة المذكورة | المصدر الخارجي | وضع عربية اليوم | الحكم |
|---|---|---|---|
| مواقيت | Aladhan | بروكسي `/api/prayer-times` موجود | **لا نستبدله**؛ نضيف لاحقًا حسابًا محليًا (adhan-js) كاحتياط أوفلاين |
| قرآن نص | alquran.cloud | بيانات Git تحت `/data` | **لا نعتمد عليه في الإنتاج** |
| قرآن صوت | quran.com API | EveryAyah + `/api/mushaf/audio` | **لا نستبدله** |
| تفسير | quranenc.com | `data/tafsirs` محلي | **لا نستبدله**؛ مقارنة مصادر فقط |
| حديث | hadis-api-id (Vercel) | `data/hadith` محلي | **لا ندمجه** — بعيد عن Contabo ومخاطر اعتماد |
| أذكار | nawafalqari/azkar-api + Hisnmuslim API | `data/adhkar` + حصن المسلم | هجين مقارنة محتوى فقط |
| إذاعة | radio.json على Vercel | `/resources` فيها إذاعة القاهرة كرابط | هجين: توسيع قائمة محطات **بعد التحقق من الروابط والترخيص** في Git |

### غير المناسب
- بناء منتج عربية كـ«غلاف» لهذه الـ APIs البعيدة.
- أي مسار يمر عبر Vercel كاعتماد إنتاج.
- استبدال طبقات الدراسة (إعراب/صرف/دلالة) بـ API نص عام.

### الخلاصة لـ Islamic-APIs
**دليل مفيد للمبتدئين، ضعيف كأساس لعربية.** القيمة الوحيدة العملية الآن: أفكار توسيع الإذاعة + تأكيد أن عربية تغطي أصلًا معظم البنود محليًا.

## 3) Flutter-Islamic-Muslim-Application — الحكم التفصيلي

### ما هو؟
تطبيق «كل أدوات المسلم»: مصحف مفسَّر/مترجم/صوت، سبحة، أذكار، مكتبة فيديو، لوحة أدمن، مواقيت، تنبيهات.  
المستودع يعرض README ولقطات فقط؛ **طلب السورس كود عبر نموذج** — ليست رخصة OSS جاهزة للدمج.

### التداخل مع عربية (ويب)

| ميزة التطبيق | عربية | ملاحظة |
|---|---|---|
| مصحف + تفسير + ترجمة + صوت | موجود وأعمق (طبقات كلمة بكلمة) | لا ننسخ |
| سبحة / أذكار | `/adhkar`، `/adhkar/tasbeeh` | موجود |
| مواقيت | بطاقة مواقيت + `/qibla` | موجود (بدون أذان صوتي/إشعار نظام) |
| لوحة أدمن | `/admin`، محرر أذكار | موجود بهوية مختلفة |
| مكتبة فيديو/دورات | غير موجود كمنتج أساسي | مؤجّل / خارج الجوهر إلا كمحتوى تراث لاحق |
| تنبيهات جوال | غير موجود | مؤجّل (PWA/إشعار لاحقًا) |

### الحكم
**غير مناسب للدمج البرمجي الآن** للأسباب التالية:

1. الكود غير منشور للاستخدام الحر في المستودع.
2. المسار التقني Flutter بينما عربية = Next.js على Contabo؛ الجوال مؤجّل في الدستور.
3. تكرار وظيفي لسطح موجود دون طبقة التحليل التي تميّز عربية.

**ما يمكن أخذه لاحقًا (بعد موافقة + فتح الكود/الترخيص):** أفكار UX للتنقل بين الأدوات، تنظيم لوحة «يوم المسلم»، سلوك التنبيهات — **كمرجع تصميم فقط** داخل الويب/PWA.

## خطة الدمج والتطوير الكاملة

### قواعد ثابتة لكل مرحلة

1. **لا نستبدل** بيانات Git تحت `/data` بـ API بعيد.
2. **الإنتاج = Contabo** فقط (PM2 + Nginx). لا Vercel.
3. **هوية بصرية عربية** (teal / RTL) — لا استنساخ واجهات التطبيقات العامة.
4. كل مصدر بيانات جديد يحتاج سطر مصدر في `SOURCES.md` أو ما يعادله + رخصة.
5. قبل كل مرحلة منتج: موافقة مالك صريحة («نفّذ المرحلة X»).

## ماذا نرفض صراحة (قائمة سوداء تشغيلية)

1. دمج مستودع Flutter كمنتج فرعي داخل monorepo عربية.
2. الاعتماد الإنتاجي على `hadis-api-id.vercel.app` أو أي API حديث بعيد بدل `data/hadith`.
3. استبدال `data/translations` و`data/tafsirs` بـ alquran.cloud / quranenc كمصدر وحيد حي.
4. نشر عربية على Vercel بسبب هذه القوائم.
5. تحويل الصفحة الرئيسية إلى لوحة «أدوات مسلم» على حساب هوية التحليل كلمة بكلمة.
6. نسخ واجهات أرجوانية/SaaS من التطبيقات المذكورة — الهوية ثابتة.
