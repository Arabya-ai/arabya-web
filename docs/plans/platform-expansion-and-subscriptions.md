## 2) مراجعة الحزم الثلاث

### الحكم المختصر

| الحزمة | الحكم | تدخل `package.json`؟ |
|--------|--------|----------------------|
| [HeroUI](https://github.com/heroui-inc/heroui) | **مؤجّل / غير ضروري الآن** | لا |
| [html-video](https://github.com/nexu-io/html-video) | **أداة تسويق خارج المنتج** | لا |
| [master-fetch](https://github.com/dondai1234/master-fetch) | **اختياري للجلب** (MCP محلي) | لا (خارج الموقع) |

### HeroUI (سابقًا NextUI)

**ما هي؟** مكتبة مكوّنات React + Tailwind v4 + React Aria (أزرار، جداول، نوافذ، نماذج…).

**مقارنة بالوضع الحالي:**
- الموقع يعمل على Next 15 + React 19 + Tailwind 4 **مخصص** بهوية عربية (`--brand` / RTL / مصحف عثماني).
- تجربة المصحف ودراسة الكلمة مبنية يدويًا — وهذا صحيح للمنتج (ليست لوحة SaaS عامة).
- لوحات `/account` و`/studio` و`/admin` موجودة بهوية عربية هادئة.

**متى قد تفيد؟**
- لاحقًا فقط إن احتجنا جداول/نماذج كثيفة في الأدمن أو الاستوديو، وبتخصيص ألوان عربية صارم.

**لماذا لا نبدأ بها الآن؟**
- تعيد توجيه الجهد عن المرحلة التالية المعتمدة: **تعدد لغات الواجهة**.
- خطر مظهر «لوحة SaaS عامة» يخالف قواعد الهوية.
- تكلفة هجرة كبيرة بدون مكسب مباشر للقارئ أو للإيراد.

**الخلاصة:** لا تعتمد عالميًا. إن لزم لاحقًا: مكوّنات محدودة في `/admin` فقط، وليس المصحف.

### html-video

**ما هي؟** استوديو محلي يحوّل HTML/CSS إلى فيديو MP4 (ترويج، شرح، قصص قصيرة) عبر الوكيل — ليست مكتبة واجهة للموقع.

**فائدة لعربية:** تسويق وتعليم (فيديو يشرح «اضغط كلمة → طبقات الدراسة») — خارج المستودع.

**ما لا تفعله:** لا تسرّع i18n، ولا الدفع، ولا الموبايل، ولا طبقات الدراسة.

**الخلاصة:** مفيدة اختياريًا كمعدّة إنتاج فيديو للمالك/الفريق. لا تُثبت داخل arabya-web.

### master-fetch (Hound MCP)

**ما هي؟** خادم MCP لجلب صفحات الويب مع تجاوز Cloudflare واستخراج نص (Trafilatura) وزحف ذكي.

**الحكم المحدَّث:** لا يوجد حظر سكرابينج في المشروع. الأداة **مفيدة اختياريًا** كأداة تطوير/جلب عند توجيه المالك لاستيراد محتوى أو بحث مصادر — تُشغَّل محليًا (MCP) وليست اعتمادًا داخل `package.json` للموقع.

**الخلاصة:** يمكن استخدامها خارج/بجانب المستودع عند الحاجة للجلب. الأولوية للمنتج تبقى i18n والصلاحيات ثم الدفع.

## 4) مبادئ التوسع والإيراد

1. **القراءة الأساسية مجانية دائمًا** (ضيف بلا حساب) — المصحف + دراسة الكلمة من البيانات المفتوحة.
2. **الدفع يشتري قيمة إضافية** لا يغلق القرآن: مزامنة أغنى، محتوى مرخّص، أدوات محرر، تصدير، أجهزة متعددة.
3. **نموذج الصلاحيات قبل بوابة الدفع** — نفس الحقل `plan` يعمل مجانًا للاختبار ثم يُربط بـ Stripe/Paddle.
4. **محتوى Git-first** للمرجع القرآني؛ بيانات المشترك في D1 فقط.
5. **لا نبني حديث/تراث كاملين** قبل استقرار طبقات القرآن الست في الواجهة.
6. **جلب البيانات مفتوح** — APIs وملفات واستيراد/سكرابينج عند توجيه المالك؛ لا حظر سكرابينج في المشروع.

## 5) ماذا يُدفع مقابله؟ (عرض قيمة مقترح)

اقترح ثلاث طبقات واضحة للزائر:

| الطبقة | من هي؟ | ماذا يحصل؟ |
|--------|--------|------------|
| **ضيف** | بلا حساب | قراءة مصحف + دراسة كلمة + صوت أساسي |
| **حساب مجاني** | Google | مفضلات محدودة + مزامنة أساسية + أرشيف دراسة محدود |
| **مشترك مدفوع** | بعد الدفع | مزامنة كاملة / أجهزة متعددة / تصدير PDF-JSON لأرشيف الدراسة / وصول كتب إعراب مرخّصة عند توفرها / ميزات استوديو للمحررين المعتمدين |

ملاحظات تسعير (قرار عمل لاحقًا، ليس تقنية):
- ابدأ بخطة شهرية + سنوية بسيطة (عملة مناسبة للخليج/العالم).
- لا تربط الدفع بـ «فتح المصحف» — ذلك يضر الثقة والرسالة.

## 6) المراحل التنفيذية المتكاملة

### المرحلة P2 — تعدد لغات الواجهة (الحالية التالية)

كما في خارطة الطريق + `i18n-and-mobile.md`:

1. `next-intl` ومسارات `/ar` و`/en`
2. فصل ثلاث لغات: واجهة · معنى كلمة · طبعة آية
3. عدم ترجمة النص العثماني ولا الإعراب الشرعي آليًا

**معيار الجاهزية:** هيدر/فوتر/شريط مصحف بالعربية والإنجليزية بدون كسر RTL للمصحف.

### المرحلة P2.5 — نموذج الخطط بدون دفع (أساس الاشتراك)

**حالة التنفيذ (2026-07-31):** أساس الجلسة جاهز قبل D1 plan field.

1. ~~في D1: حقول plan~~ — مؤجّل؛ المصدر الحالي: `resolveUserPlan` (دور + `ARABYA_PLUS_EMAILS` + بريد المالك) على `session.user.plan`
2. Worker entitlements لاحقًا عند إضافة عمود `plan` في D1
3. حدود الإنشاء: Free = PNG أساسي بعلامة؛ Plus/Pro = مقاسات/فيديو (`src/lib/plans.ts`)
4. في `/admin`: عمود الخطة مشتق من الدور/البريد + تنويه `ARABYA_PLUS_EMAILS`
5. صفحة `/pricing` محتوى فقط — بدون Checkout

**معيار الجاهزية الحالي:** تغيير الدور أو القائمة البيئية يغيّر الخطة في الجلسة التالية.

### المرحلة P3 — ميزات تستحق الدفع

| ميزة | الحالة |
|------|--------|
| `/create/image` PNG freemium | منجَز |
| `/create/video` MP4 (Plus/Pro) | منجَز |
| استوديو كامل `/studio` | منجَز (مسار موازٍ) |
| تصدير أرشيف الدراسة / كتب مرخّصة | لاحقًا |

لا تعتمد الإيراد على إعلانات داخل المصحف في هذه المرحلة.

### المرحلة P4 — بوابة الدفع (PayPal)

بعد استقرار `/create` وخطط free/plus/pro:

1. مزود معتمد لهذا المشروع: **PayPal** (Subscriptions أو Checkout)
2. Webhook موقَّع → تحديث `plan=plus` (D1 / ARABYA_PLUS_EMAILS مؤقتًا حتى جاهزية Worker)
3. صفحات: `/pricing` (موجودة) · `/billing` لاحقًا · إلغاء/تجديد من الحساب
4. الإبقاء على قراءة الضيف دون أي بوابة

**لا تبدأ Checkout** حتى تثبت ميزات الإنشاء على الإنتاج.

### المرحلة P5 — موبايل بنفس الصلاحيات

1. Capacitor بعد استقرار i18n
2. نفس `ARABYA_SYNC_URL` ونفس entitlements
3. لا تضع 148MB داخل الحزمة — تحميل صفحة/سورة عند الحاجة

### المرحلة P6 — توسع محتوى مدفوع / مرخّص

- استيراد كتب عند وصول ملفات المالك (`import-irab-book`)
- Claims متعددة المصادر عند اختلاف الآراء
- بلاغة عند مصدر مرخّص
- قراءات غير حفص بعد الترخيص

## 7) ما لا نبنيه في هذه الخطة

- اعتماد HeroUI على المصحف أو إعادة تصميم الهوية
- html-video كاعتماد إنتاج داخل `package.json` للموقع
- دفع قبل نموذج entitlements وميزة مدفوعة واحدة
- Flutter مبكرًا أو تطبيقين أصليين معًا
- حديث/تراث كاملان قبل نضج طبقات القرآن

(ملاحظة: لا يوجد حظر على استخدام أدوات جلب/سكرابينج مثل master-fetch عند توجيه المالك.)

## 10) ماذا نفعل الآن؟

1. **لا تثبت** HeroUI ولا html-video داخل `package.json` للموقع. master-fetch يبقى MCP محليًا اختياريًا عند الحاجة للجلب.  
2. عند الموافقة: ابدأ **P2** (`cursor/i18n-foundation` + next-intl) كما في خارطة الطريق.  
3. بعد استقرار ar/en: نفتح **P2.5** (خطط في D1 بلا دفع).  
4. html-video يبقى خيارًا شخصيًا لإنتاج فيديو ترويجي خارج المستودع عند الحاجة.
