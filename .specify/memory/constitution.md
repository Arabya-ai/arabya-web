# دستور عربية (Arabya Constitution)

هذا الدستور يحكم كل عمل Spec Kit في هذا المستودع. المواصفات والخطط والمهام والتنفيذ تلتزم به. لا يُكسر مبدأ هنا من أجل سرعة التسليم.

## Core Principles

### I. Git-first للمحتوى القرآني

نص القرآن، الكلمات، الإعراب، التفاسير، والفهارس تُحفظ في `/data` داخل Git. لا تُنقل هذه البيانات إلى جداول خارجية (Sheets، Supabase، D1) كمصدر حقيقة. كل إصدار من المحتوى يُراجع عبر commit. المصادر تُذكر؛ لا يُختلق إعراب أو تفسير.

### II. بيئتان متكافئتان: محلي و Contabo

المنتج واحد في:

| بيئة | عنوان | تشغيل |
|------|--------|--------|
| محلي | `http://localhost:3000` | `npm run dev` |
| إنتاج | `https://www.arabya.org` و `https://www.arabyaai.com` | Contabo VPS + PM2 + Nginx |

النطاقان على Contabo يخدمان **نفس التطبيق**. لا يُفترض Vercel إنتاجًا. التطوير يُختبر محليًا أولًا، ثم يُنشر إلى Contabo بعد الدمج في `main` عبر `scripts/contabo-deploy.sh`. أي ميزة يجب أن تعمل في البيئتين أو تُوثَّق صراحة كاستثناء (مثل مفاتيح OAuth).

### III. لا كسر للتلاوة ولا لصفحة المصحف

المصحف (604 صفحة)، التلاوة، ودراسة الكلمة مسارات حرجة. لا تُدمج تغييرات تكسر التخطيط RTL، أو الصوت، أو حجم صفحة المصحف، أو الترطيب (hydration). إصلاح مسار واحد لا يبرر كسر مسار آخر (`useQuranAudio` مقابل التفضيلات مقابل الدراسة).

### IV. حسابات المستخدم على قرص Contabo

المصدر المعتمد لحسابات Google والمزامنة السحابية هو **SQLite على Contabo** عند `ARABYA_USER_SYNC_ENABLED=1`. Cloudflare D1 / Worker أرشيف فقط. لا تُهاجر بيانات المستخدم إلى Neon أو Vercel KV دون تعديل هذا الدستور. الأسرار تبقى في `.env*` غير الملتزم؛ لا تُطبع في السجلات ولا في Git.

### V. البساطة والاختبار قبل النشر

ابدأ بأضيق تغيير يحقق المطلوب. اختبارات الوحدة وE2E الموجودة تُحدَّث مع السلوك. لا يُرفع إلى Contabo من فرع تجريبي غير مدمج إلا بطلب صريح من المالك. لا تُحذف وثائق Contabo أو سكربتات `deploy/contabo/` دون بديل عامل.

## المنصة الكاملة (نطاق الدستور)

يغطي الدستور الموقع كاملًا وليس شاشة واحدة:

- البوابة، المصحف، السور، الآيات، الأجزاء، الجذور
- لوحة الدراسة (إعراب، معجم، ترجمة، تفسير)
- الحسابات، لوحة التحكم، المظهر
- الاستوديو / إنشاء الآيات
- التسميع، القراءات، الكتب، الخصوصية والصفحات القانونية
- واجهات API الداخلية (`/api/*`) وسكربتات البيانات

الميزات المؤجلة (بلاغة، أحاديث/تراث كامل، دفع، `arabya.ai`) تبقى مؤجلة حتى تُفتح بمواصفة صريحة.

## الاستضافة والنشر

- الإنتاج: Contabo (ServerAvatar / Nginx → `127.0.0.1:3000` → PM2).
- التحديث بعد دمج `main`: `cd /var/www/arabya-web && bash scripts/contabo-deploy.sh`.
- Google OAuth: Origins وRedirect URIs لكلا النطاقين + localhost للتطوير.
- Analytics الإنتاج: Cloudflare Web Analytics وليس Vercel Analytics.
- لا تُرفع ملفات Spec Kit (`.specify/`, `specs/`, مهارات Cursor) كشرط لعمل الموقع للزائر؛ هي أدوات تطوير في Git.

## سير العمل (Spec Kit)

1. `/speckit-constitution` — تحديث المبادئ عند تغير الحوكمة فقط.
2. `/speckit-specify` — ماذا ولماذا، لكل البيئتين، بدون قفز للكود.
3. `/speckit-plan` — كيف (Next.js، SQLite، Contabo، سكربتات البيانات).
4. `/speckit-tasks` — مهام قابلة للمراجعة.
5. `/speckit-implement` — التنفيذ على فرع مستقل ثم اختبار محلي.
6. الدمج في `main` ثم النشر إلى Contabo بقرار المالك.

## Governance

- هذا الدستور أعلى من أسلوب الترميز العابر ومن طلبات «أسرع فقط».
- تعديل مبدأ يتطلب تحديث هذا الملف (إصدار + تاريخ) وذكر الأثر على المواصفات المفتوحة.
- المراجعات والـ PR تتحقق من: سلامة المحتوى القرآني، تكافؤ المحلي/Contabo، عدم تسريب الأسرار، وعدم كسر المصحف/الصوت.
- التعقيد الزائد يُرفض ما لم يُبرَّر في المواصفة.
