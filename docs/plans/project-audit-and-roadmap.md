## 1) ماذا يعني هذا الملف؟

هذا الملف يجيب على ثلاثة أسئلة فقط:

1. ما حالة المشروع الآن؟
2. ما الذي يجب إصلاحه أو تطويره أولًا؟
3. ما ترتيب العمل حتى نصل إلى تعدد اللغات ثم تطبيق الموبايل؟

---

## 2) حالة المشروع باختصار

### ما يعمل جيدًا
- قراءة المصحف ودراسة الكلمة (إعراب، صرف، ترجمة، تفسير الآية)
- صوت الآية / الكلمات / السورة مع مشغّل
- ترجمات آيات متعددة (حوالي 24 طبعة) بأسماء بلغتها الأصلية
- حساب المستخدم والمزامنة والاستوديو
- فحص البيانات `validate-data` ناجح

### ما يعيق التوسع
- واجهة الموقع عربية فقط (النصوص مكتوبة داخل الكود)
- ملفّات الدراسة كبيرة ومتداخلة (صعب ترجمتها أو نقلها للموبايل)
- بيانات المحتوى كبيرة جدًا (~148MB) ولا تصلح لحزمة تطبيق كاملة
- لا يوجد تطبيق موبايل بعد، ولا PWA كامل (بدون Service Worker)

### فحص سريع للجودة
| الفحص | النتيجة |
|--------|---------|
| Lint | لا أخطاء (بعض التحذيرات البسيطة) |
| الاختبارات | أُصلحت مشاكل `StudyModeTabs`؛ يفترض أن تكون خضراء |
| البيانات | ناجحة لـ 114 سورة |
| CI | lint ثم test ثم validate-data ثم build |

---

## 3) ثلاث لغات مختلفة — لا تخلط بينها

هذا أهم مبدأ قبل أي تطوير لغات أو موبايل:

| النوع | معناه | مثال |
|--------|--------|------|
| لغة الواجهة | أزرار القوائم والصفحات | العربية أو English في الهيدر |
| لغة ترجمة الكلمة | معنى الكلمة في اللوحة والجدول | عربي / English / Bahasa Indonesia / اردو |
| طبعة ترجمة الآية | اختيار ترجمة كاملة للآية | Saheeh International أو Diyanet |

كل نوع يُحفظ ويتغير لوحده. لا نجعل زرًا واحدًا يغيّر الثلاثة معًا.

---

## 4) المشكلات الحالية وما تم إصلاحه

### تم إصلاحه مؤخرًا
- فشل اختبارات التبويبات بسبب أدوات غير موجودة في بيئة الاختبار
- خطر سكربت قديم يمسح فهرس الترجمات الكبيرة
- تكرار معرّف `study-panel` في الصفحة

### ما زال يحتاج عملًا قريبًا
1. توحيد مفاتيح التخزين المحلي في ملف واحد
2. تنظيف تحذيرات ESLint البسيطة
3. تقسيم ملف `MushafPageStudio` الكبير إلى أجزاء أصغر
4. منع جلب التفسير مرتين (مرة للصفحة ومرة للوحة الكلمة)
5. تحسين الصوت للخلفية على الموبايل لاحقًا (Media Session الآن)

### مؤجّل عمدًا (ليس عطلًا)
- البلاغة
- الحديث والتراث
- قراءات غير حفص
- الاشتراكات المدفوعة
- Claims متعددة المصادر (حتى تصل كتب مرخّصة)

---

## 5) ما الموجود الآن… وماذا نطوّره أولًا؟

### أولًا: قلب المنتج (الدراسة)
| الوظيفة | الحالة | التطوير المطلوب |
|----------|---------|------------------|
| دراسة الكلمة على المصحف | موجودة | تبسيط الكود + أداء + اختبارات بسيطة |
| الصوت | يعمل على الويب | جاهزية أفضل للموبايل لاحقًا |
| ترجمات الآيات | موجودة | تجميع القائمة حسب اللغة لسهولة الاختيار |

### ثانيًا: الحساب والمزامنة
| الوظيفة | الحالة | التطوير المطلوب |
|----------|---------|------------------|
| الحساب والمفضلات وأرشيف الدراسة | موجودة | مزامنة تفضيلات اللغة لاحقًا + اختبارات API |

### ثالثًا: محتوى مرخّص لاحقًا
- كتب الإعراب: جاهزة للاستيراد عند وصول الملفات
- القراءات الإضافية: فهرس فقط حتى الترخيص

---

## 6) كيف نعيد تنظيم المشروع؟

### أ) تقسيم شاشة المصحف
بدل ملف واحد ضخم:

```text
MushafPageStudio (المنسّق)
  ├── شريط الأدوات
  ├── نص المصحف
  ├── لوحة دراسة الكلمة
  ├── تبويبات الصفحة
  └── مشغّل السورة
```

### ب) عميل API موحّد (مهم للموبايل)
كل طلبات `/api/...` تمر من مكان واحد، حتى نستطيع تغيير عنوان السيرفر في التطبيق.

### ج) بيانات الموبايل
لا نضع 148MB داخل التطبيق.  
نحّمل السورة أو الصفحة عند الحاجة من السيرفر أو CDN.

### د) طبقة مشتركة للكود الأساسي
أنواع البيانات ومعرّفات الكلمات والصرف في مكان بلا React، ليسهُل استخدامها لاحقًا في Flutter إن لزم.

## 7) خطة العمل بالمراحل

### المرحلة 0 — تثبيت الأساس ✅ مكتملة
الهدف: مشروع مستقر قبل اللغات.

1. التأكد أن الاختبارات والبناء خضراء
2. ملف مفاتيح التخزين الموحّد (`src/lib/storage-keys.ts`)
3. تنظيف تحذيرات ESLint
4. تحديث تعليمات المطورين (سكربت الترجمات + تحذير junction الـ Worker)

---

### المرحلة 1 — ترتيب كود الدراسة ✅ مكتملة
الهدف: نفس التجربة للمستخدم، وكود أسهل للترجمة.

1. تقسيم شاشة المصحف (`src/components/mushaf/…`)
2. توحيد كاش التفسير (`ensureTafsirSurah` مشترك)
3. تجميع قائمة ترجمات الآية حسب اللغة
4. اختبارات لكاش الدراسة وعميل API
5. Media Session للصوت على الويب
6. عميل API موحّد + طبقة `src/domain` + أنواع `content-manifest`

**مؤجّل عمدًا (ليس عائق إنتاج الآن):** مزامنة تفضيلات لغة الواجهة — مع المرحلة 2.

---

### المرحلة 2 — تعدد لغات الواجهة (2 إلى 4 أسابيع)
الهدف: الموقع يتكلم العربية والإنجليزية أولًا.

التفاصيل التقنية في: `docs/plans/i18n-and-mobile.md`

الخطوات العملية:

1. تثبيت next-intl
2. مسارات حسب اللغة مثل `/ar/...` و `/en/...`
3. اتجاه الصفحة `rtl` أو `ltr` حسب اللغة
4. ترجمة الهيدر والفوتر وأزرار الحساب أولًا
5. ثم ترجمة نصوص شريط المصحف وأوضاع الصفحة
6. الإبقاء على ترجمة الكلمة وطبعة الآية منفصلتين عن لغة الواجهة
7. بعد استقرار العربية والإنجليزية: إضافة لغات مثل الإندونيسية والتركية والأردو للواجهة

**لا نترجم في هذه المرحلة:** نص المصحف العثماني، ولا نغيّر محتوى الإعراب القرآني.

---

### المرحلة 3 — تطبيق الموبايل
الهدف: وصول للمتاجر بدون إعادة بناء كل شيء مبكرًا.

الترتيب المقترح:

1. بعد استقرار لغات الواجهة الأساسية
2. إعداد عميل API + صوت قابل للعمل على الجهاز
3. **Capacitor** كأول غلاف سريع لنفس الموقع
4. **Flutter** فقط إذا احتجنا أداءً أصليًا أقوى لاحقًا

| الخيار | متى نختاره؟ | ملاحظة |
|---------|-------------|--------|
| Capacitor | أول إطلاق سريع | يعيد استخدام موقع عربية |
| Flutter | إذا صار الموبايل المنتج الأساسي | يحتاج إعادة بناء الواجهة |
| Kotlin + Swift | غير مناسب الآن | تكلفة مضاعفة لفريق صغير |

---

### المرحلة 4 — توسع لاحق (بعد استقرار اللغات)
- كتب إعراب مرخّصة في الواجهة
- Claims عند وجود أكثر من مصدر
- البلاغة عند توفر مصدر مرخّص
- تحسينات صوت وقراءة وحساب

### ما لا نبنيه الآن
- حديث وتراث كاملان
- بوابة دفع
- تطبيقان أصليان معًا من اليوم الأول

---

## 8) جدول الأسبوعين القادمين (مقترح عملي)

### الأسبوع 1
- إكمال بقايا المرحلة 0 (مفاتيح التخزين + تنظيف التحذيرات)
- بدء المرحلة 1: تقسيم شاشة المصحف وتجميع الترجمات

### الأسبوع 2
- بدء المرحلة 2: next-intl للعربية والإنجليزية على الهيدر/الفوتر
- ثم نصوص شريط المصحف
- مراجعة سريعة للتجربة

بعد ذلك نقرر معًا:
- هل نكمل لغات واجهة إضافية؟
- أم نبدأ غلاف Capacitor؟

## 9) قائمة تحقق قبل يوم اللغات الأول

- [ ] `npm run test` ناجح
- [ ] `npm run lint` ناجح
- [ ] `npm run build` ناجح
- [ ] لا نستخدم أمر الترجمات القديم الذي يمسح الفهرس
- [ ] متفقون على فصل اللغات الثلاث (واجهة / كلمة / آية)
- [ ] نبدأ بـ العربية + الإنجليزية فقط للواجهة
- [ ] قرار الموبايل مؤجّل حتى استقرار أساس اللغات

---

## 10) مخاطر يجب تجنبها

1. ترجمة آلية لنصوص شرعية أو نحوية دون مراجعة
2. كسر اتجاه المصحف RTL عندما تصبح الواجهة إنجليزية LTR
3. إضافة عشرات الترجمات بلا حاجة (يضخّم المشروع)
4. بدء Flutter قبل استقرار دراسة الكلمة واللغات
5. تشغيل `next build` أثناء `next dev` (يفسد الملفات المؤقتة)

---

## 11) ماذا نفعل الآن؟

المرحلتان 0 و1 **مكتملتان** وجاهزتان للإنتاج ضمن النطاق الحالي.

الخطوة التالية (عند الموافقة فقط — مرحلة جديدة):

1. فتح فرع `cursor/i18n-foundation`
2. تثبيت next-intl والبدء بالعربية والإنجليزية في الهيدر والفوتر
